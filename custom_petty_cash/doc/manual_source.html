โมดูล custom_petty_cash v1.4 — สำหรับฝ่ายบัญชี | บริษัท ออโต้โซน จำกัด | สิงหาคม 2569

ภาพรวมระบบ

สาขาไม่ต้องใช้ระบบ — สาขาจ่ายเงินจากกองเงินสดย่อย (วงเงิน 4,000 บาท/สาขา) เก็บใบเสร็จ กรอกฟอร์มกระดาษของสาขา แล้วส่งซองเอกสารมาให้ฝ่ายบัญชี ฝ่ายบัญชีเป็นผู้บันทึกเข้าระบบทั้งหมด ระบบจะช่วยคุมยอดเงินแต่ละกอง สร้าง vendor bill พร้อม analytic สาขา จ่าย+หักภาษีให้จบในจอเดียว และพิมพ์เอกสารประกอบการลงบัญชี

① คีย์ใบเบิก→ ② คีย์ใบเคลียร์→ ③ Post + จ่ายทั้งชุด→ ④ เติมเงินคืนสาขา

เมนูทั้งหมดอยู่ที่แอป Accounting → เงินสดย่อย (แถบบนสุด ระหว่าง Reporting กับ Configuration) มีเมนูย่อย 5 ตัว: ใบเบิก / ใบเคลียร์ / ขอเติมเงิน / นับเงินสด / กองเงินสดย่อย

ตั้งค่าครั้งแรก (ทำครั้งเดียว)

ไปที่ เงินสดย่อย → กองเงินสดย่อย — กองทั้ง 27 สาขาถูกสร้างไว้แล้วพร้อม journal และ analytic ประจำสาขา ให้เข้าไปกรอกเพิ่ม 2 ช่องต่อกอง:

  • ผู้ถือเงิน = ธุรการสาขา
  • ผู้อนุมัติ = ผู้จัดการสาขา
Tip: สองชื่อนี้จะถูกพิมพ์ใต้ช่องลายเซ็นบนฟอร์มอัตโนมัติ ช่วยให้ไม่ต้องเขียนชื่อเองทุกใบ

หน้ากองเงินสดย่อยยังแสดงยอด เงินคงเหลือในกอง / เบิกค้างเคลียร์ / รอเติมเงิน ของทุกสาขา ใช้ตรวจสถานะได้ตลอดเวลา

การสร้างกองเงินสดย่อยกองใหม่ (เช่น กองประจำแผนก หรือสาขาเปิดใหม่)

หลักคิดก่อนลงมือ: กอง 1 กอง = กระเป๋าเงิน 1 ใบ = cash journal 1 ตัวของกองนั้นโดยเฉพาะ ส่วน journal ตั้งหนี้ใช้ PCB ตัวเดียวร่วมกันทุกกอง — ห้ามสร้าง journal ตั้งหนี้ใหม่

ห้ามสร้าง journal จากปุ่ม New/สร้าง ในช่อง Journal ของฟอร์มกอง — journal ที่สร้างจากหน้าต่างเล็กนั้นจะเป็น journal เปล่าที่ config ไม่ครบ (ไม่มี Cash Account 111002, ไม่มี outstanding account) ใช้แล้วกดจ่ายเงินจะไม่เกิดรายการบัญชีแบบเงียบ ๆ ให้ใช้วิธี Duplicate ตามขั้นตอนข้างล่างเท่านั้น

1สร้าง cash journal ของกอง

ทำได้ 2 แบบ แล้วแต่ว่าฐานข้อมูลมี journal เงินสดย่อยอยู่แล้วหรือไม่:

แบบ ก — ฐานมี journal เงินสดย่อย (PCxxx) อยู่แล้ว → ใช้วิธี Duplicate (เร็วและพลาดยาก)

Accounting → Configuration → Journals เปิด journal เงินสดย่อยของสาขาใดก็ได้ (เช่น PCHO)

  • กดเมนู ⚙ Action → Duplicate — จะได้ journal ใหม่ที่ config หลักติดมา (Type, Cash Account)
  • แก้ Journal Name = "เงินสดย่อย <ชื่อกอง>" เช่น เงินสดย่อย แผนกจัดซื้อ
  • แก้ Short Code = PC + รหัสย่อของกอง (รวมไม่เกิน 5 ตัวอักษร, ห้ามซ้ำกับที่มี) เช่น PCPUR
  • กด Save
  • แต่แท็บ Incoming/Outgoing Payments จะไม่ติดมาด้วย — Odoo ไม่ก๊อปช่อง Outstanding Account ตอน Duplicate (ได้ค่าว่างเสมอ) ต้องเข้าไปตั้ง 111001 บัญชีพักเงินจ่าย เองตามข้อ 5-6 ของแบบ ข

แบบ ข — ฐานยังไม่มี journal เงินสดย่อยเลย (เครื่องฝึก/ฐานใหม่) → สร้างจากศูนย์

Accounting → Configuration → Journals → New แล้วกรอกตามลำดับนี้ (ลำดับสำคัญ — ฟอร์ม journal จะโชว์ช่องเพิ่มตาม Type ที่เลือก):

  1. Type = Cash (เงินสด) ก่อนเป็นอย่างแรก — เลือกแล้วแท็บ Incoming/Outgoing Payments กับช่องบัญชีต่าง ๆ จะโผล่มา (ถ้ายังไม่เลือก Type ฟอร์มจะมีแค่ไม่กี่ช่อง อย่าตกใจ)
  2. Journal Name = "เงินสดย่อย <ชื่อกอง>"
  3. Short Code = PC + รหัสย่อ (ไม่เกิน 5 ตัว) เช่น PCPUR
  4. Cash Account (บัญชีเงินสด) = บัญชีเงินสดย่อยของผังบัญชี (ฐานจริงของบริษัท = 111002 Petty Cash) — Odoo มักสร้างบัญชีใหม่ให้เองอัตโนมัติ ต้องเปลี่ยนมาใช้บัญชีเงินสดย่อยที่มีอยู่ ห้ามปล่อยเป็นบัญชีที่ระบบสร้างเอง และทุกกองใช้บัญชีเงินสดย่อยตัวเดียวกัน (แยกกองด้วย journal ไม่ใช่ด้วยบัญชี)
  5. แท็บ Outgoing Payments บรรทัด Manual → ช่อง Outstanding Payments Account = 111001 บัญชีพักเงินจ่าย (ตัวเดียวกับใบสำคัญจ่าย PVC — พิมพ์ 111001 ค้นเจอเลย) — ถ้ามองไม่เห็นคอลัมน์นี้ ให้กดปุ่มปรับคอลัมน์ (ไอคอนมุมขวาของตาราง) แล้วติ๊กเปิด "Outstanding Payments Account"
  6. แท็บ Incoming Payments ตั้ง Outstanding Receipts Account = 111001 เช่นกัน (ใช้ตอนรับเงินทอนคืนกอง) — ต้องตั้งทั้งสองแท็บ อย่าลืมฝั่งรับ
  7. กด Save
ของที่โมดูลเตรียมให้อัตโนมัติ: ตอนติดตั้ง/อัพเกรดโมดูล ระบบสร้าง journal PCB ตั้งหนี้เงินสดย่อย ให้เองถ้ายังไม่มี และเปิดตัวกรองให้ช่อง Outstanding ค้นบัญชี 111001 บัญชีพักเงินจ่าย (ประเภทเงินสด ซึ่งปกติ Odoo จะกรองออก) เจอได้ตามปกติ — และถ้าเผลอผูก journal ที่ยังไม่ได้ตั้ง Outstanding เข้ากอง ระบบจะเด้งเตือนทันทีพร้อมบอกวิธีแก้ (กันเหตุกดจ่ายแล้วไม่เกิดรายการบัญชี) ห้ามแก้ประเภทบัญชีใด ๆ เพื่อหลบตัวกรอง — (หมายเหตุ: บัญชีพักแยก 111007 ที่เคยมีในเวอร์ชันก่อน ถูกยกเลิกแล้วตามมติฝ่ายบัญชี 27 ส.ค. 69 ทุกกองใช้ 111001 ร่วมกับใบสำคัญจ่าย PVC เหมือนเดิม)

ถ้าฐานยังไม่มี journal ตั้งหนี้กลาง PCB ให้สร้างเพิ่มอีกตัว (ทำครั้งเดียว ทุกกองใช้ร่วมกัน): Journals → New → Type = Purchase → ชื่อ "ตั้งหนี้เงินสดย่อย" → Short Code PCB → Save (ไม่ต้องตั้ง Default Account — โมดูลใส่บัญชีให้รายบรรทัดจากใบเคลียร์อยู่แล้ว)

ตรวจ 3 จุดนี้ก่อนออกจากหน้า journal เงินสด (ทำทั้งแบบ ก และ ข — โดยเฉพาะแบบ ก ที่ Outstanding ไม่ติดมากับการ Duplicate):

จุดตรวจค่าที่ต้องเป็น

Cash Account (บัญชีเงินสด)111002 Petty Cash
แท็บ Outgoing Payments → Outstanding Payments Account111001 บัญชีพักเงินจ่าย — ถ้าว่าง กด Pay แล้วจะไม่เกิด JE เงียบ ๆ (ระบบจะบล็อกตอนผูกกองให้อีกชั้น)
อย่าตั้งค่า "บัญชีที่ใช้ได้ (Allowed accounts)" ในแท็บ การตั้งค่าขั้นสูง → การควบคุม-การเข้าถึง — ปล่อยว่างไว้ ถ้าไปใส่ลิสต์บัญชี ระบบจะบล็อกบิลที่ใช้บัญชีนอกลิสต์ทันที (error: "คุณไม่สามารถใช้บัญชีนี้ ... ในสมุดรายวันนี้ได้")

2สร้างกองเงินสดย่อย

เงินสดย่อย → กองเงินสดย่อย → New แล้วกรอก:

ช่องวิธีกรอก
รหัสสาขารหัสย่อของกอง (ห้ามซ้ำ) เช่น PUR — ใช้โชว์หน้าเอกสารทุกใบ
ชื่อกองชื่อเต็ม เช่น เงินสดย่อยแผนกจัดซื้อ
วงเงินวงเงินคงที่ของกอง (สาขามาตรฐาน 4,000)
Journal เงินสดสาขาเลือก journal ที่ duplicate ไว้ในขั้นตอนที่ 1 จากลิสต์ — ห้ามกด New สร้างในช่องนี้
Journal ตั้งหนี้PCB ตั้งหนี้เงินสดย่อย เสมอ ทุกกองใช้ตัวเดียวกัน — ห้ามสร้างแยกต่อกอง (ถ้าฐานยังไม่มี PCB ให้สร้างครั้งเดียวตามขั้นตอนที่ 1 แบบ ข)
Analytic สาขาanalytic ของสาขา/หน่วยงานเจ้าของกอง — ทุกบรรทัดบิลของกองนี้จะติด analytic ตัวนี้อัตโนมัติ
ผู้ถือเงิน / ผู้อนุมัติชื่อธุรการและผู้จัดการ — ไปโชว์ใต้ช่องลายเซ็นบนฟอร์มพิมพ์

3ทดสอบให้ครบวงจรก่อนใช้จริง

  • คีย์ใบเบิกทดสอบ 1 ใบ (เช่น 100 บาท) → ยืนยัน → เงินคงเหลือในกองต้องลดลง
  • คีย์ใบเคลียร์ 1 บรรทัด → กด Post + จ่ายทั้งชุด
  • เปิดปุ่ม Vendor Bills ตรวจว่า: บิลลง journal PCB / บิลสถานะ Paid / กดดู payment แล้วมี Journal Entry เกิดจริง ใน journal ของกอง (เครดิต 111002)
  • ผ่านครบ = ลบเอกสารทดสอบ (ยกเลิกใบเคลียร์+payment ก่อน) หรือเก็บไว้เป็นรายการแรกก็ได้

อาการผิดปกติที่เจอบ่อยตอนตั้งกองใหม่

อาการสาเหตุ / วิธีแก้
สร้างบิลแล้วเด้ง "คุณไม่สามารถใช้บัญชีนี้ ... ในสมุดรายวันนี้ได้" Journal ตั้งหนี้ของกองไม่ใช่ PCB หรือ journal นั้นถูกตั้ง "บัญชีที่ใช้ได้" ไว้ → เปลี่ยนกองให้ใช้ PCB / ล้างช่องบัญชีที่ใช้ได้ในแท็บการตั้งค่าขั้นสูงให้ว่าง
กดจ่ายแล้วบิลขึ้นจ่ายแล้ว แต่หาเงินออกจากบัญชีไม่เจอ (ไม่มี JE) Outstanding Payments Account ของ cash journal ว่าง (สร้างจากปุ่ม New หรือ Duplicate มาแล้วไม่ได้ตั้ง) → ตั้ง outstanding ให้ครบ แล้วยกเลิก payment เดิมมาจ่ายใหม่
พิมพ์ 111001 ในช่อง Outstanding Account แล้วค้นหาไม่เจอ โมดูล custom_petty_cash ยังเป็นเวอร์ชันเก่า (ตัวกรองมาตรฐานของ Odoo ไม่โชว์บัญชีประเภทเงินสด) → ให้ IT อัพเดตโมดูลแล้วรีเฟรชหน้าจอ — ห้ามแก้ประเภทบัญชีเพื่อหลบตัวกรอง
เลือก journal ในฟอร์มกองแล้วเด้ง "ยังไม่ได้ตั้ง Outstanding Payments Account — ผูกกับกองไม่ได้" guard ของโมดูลทำงานถูกต้องแล้ว — journal นั้นยังตั้งค่าไม่ครบ ทำตามข้อความบนจอ: เปิด journal → แท็บ Outgoing Payments → ตั้ง Outstanding = 111001 → กลับมาบันทึกกองใหม่
แก้ประเภทบัญชี 111001 แล้วเปลี่ยนกลับเป็นเงินสดไม่ได้ — เด้ง Validation Error "configured in ... as payment debit or credit account" บัญชีที่ถูกผูกเป็น Outstanding อยู่ ระบบห้ามปิด Allow Reconciliation (ซึ่งถูกปิดอัตโนมัติเมื่อเลือกประเภทเงินสด) → เปลี่ยนกลับผ่านหน้าจอไม่ได้ ต้องให้ IT รันใน odoo shell: env['account.account'].search([('code','=','111001')]).write({'account_type': 'asset_cash', 'reconcile': True}); env.cr.commit()
ยอดทะเบียนกองปนกับกองอื่น สองกองใช้ cash journal ตัวเดียวกัน หรือเลือก journal ผิดตัว (ชื่อขึ้นต้น "เงินสดย่อย" เหมือนกัน เลือกพลาดง่าย) → แยก journal คนละตัวต่อกอง แล้วตรวจช่อง Journal เงินสดสาขาของทุกกองว่าไม่ซ้ำกัน

วงจรประจำเดือน — เมื่อซองเอกสารจากสาขามาถึง

1คีย์ใบเบิก

เงินสดย่อย → ใบเบิก → New (1 ใบต่อใบเบิกกระดาษ 1 ใบ)

  • เลือก กองเงินสดย่อย (สาขา) → ใส่วันที่เบิกจริงตามเอกสาร → ชื่อผู้ขอเบิก → จำนวนเงิน → วัตถุประสงค์
  • กด ยืนยัน (จ่ายเงินแล้ว) — ยอดเงินคงเหลือของกองสาขานั้นลดลงทันที
ตัวเตือน: ถ้ายอดเบิกเกินเงินคงเหลือในกอง ระบบจะบันทึกให้แต่ขึ้นเตือนค้างไว้ — ให้ตรวจกับสาขาว่าเงินในกล่องพอจริงหรือไม่

2คีย์ใบเคลียร์

เงินสดย่อย → ใบเคลียร์ → New เลือกกอง แล้วทำ 3 แท็บ — แต่ละแท็บมีหน้าที่ต่างกัน:

แท็บไว้ใช้กับอะไรใช้ตอนไหน
① ใบเบิกที่เคลียร์ ใบเบิกเงินที่สาขาเบิกไปก่อนหน้า (ฝั่ง "เงินออกจากกล่อง") ทุกครั้งที่กองนั้นมีใบเบิกค้างเคลียร์
② ใบเสร็จ ค่าใช้จ่ายที่ยังไม่เคยเข้าระบบ — ระบบจะสร้าง vendor bill ใหม่ให้จากบรรทัดที่คีย์ ใบเสร็จ/ใบกำกับทั่วไปในซองเอกสาร (กรณีปกติเกือบทั้งหมด)
③ จ่ายบิลตั้งหนี้ บิลที่ตั้งหนี้ในระบบอยู่แล้ว (vendor bill ที่ Post แล้ว รวมบิลจาก PO) — ระบบไม่สร้างบิลใหม่ แค่ผูกบิลเดิมเพื่อจ่ายจากกอง สาขาควักเงินสดย่อยจ่ายบิลที่บัญชีตั้งหนี้ไว้แล้ว เช่น ร้านค้ามาเก็บเงินที่สาขาก่อนรอบจ่ายบัญชีกลาง
กฎเลือกแท็บ (กันตั้งหนี้ซ้ำ): ก่อนคีย์ให้ถามว่า "บิลใบนี้เคยเข้าระบบหรือยัง?" — ยังไม่เคย → แท็บใบเสร็จ / ตั้งหนี้แล้ว → แท็บจ่ายบิลตั้งหนี้ ถ้าเอาบิลที่ตั้งหนี้แล้วไปคีย์ซ้ำในแท็บใบเสร็จ จะกลายเป็นตั้งหนี้ 2 รอบ (บิลซ้ำ เจ้าหนี้เกินจริง)

แท็บ ① ใบเบิกที่เคลียร์

พอเลือกกอง ระบบดึงใบเบิกค้างเคลียร์ของกองนั้นมาให้อัตโนมัติ หน้าที่ของบัญชีคือตรวจว่าตรงกับซองเอกสาร:

  • ใบเบิกใบไหนยังไม่เคลียร์รอบนี้ (สาขายังถือเงินอยู่ ยังไม่ส่งบิลมา) → ลบแถวนั้นออก จะค้างไว้เคลียร์รอบหน้า
  • ยอดรวมของแท็บนี้ = ช่อง "ยอดเบิก" ท้ายใบเคลียร์ — ใช้เทียบกับยอดใช้จ่ายจริงเพื่อหาเงินทอน
  • เมื่อกดสร้างบิล ใบเบิกในแท็บนี้จะเปลี่ยนสถานะเป็น "เคลียร์แล้ว" อัตโนมัติ

แท็บ ② ใบเสร็จ

คีย์ทีละใบเสร็จ: วันที่ / ร้านค้า / เลขที่ใบเสร็จ / รายการ / หมวดค่าใช้จ่าย (บัญชี GL) / จำนวนเงิน / ภาษี

  • จำนวนเงิน กรอกได้สองแบบ: ยอดก่อน VAT (ปกติ) หรือติ๊ก "ยอดรวม VAT" เมื่อใบเสร็จโชว์แต่ยอดรวม — ระบบถอด VAT ย้อนให้เอง
  • หัก ณ ที่จ่าย: รายการค่าบริการ (ค่าซ่อม ค่าจ้าง ฯลฯ) เลือกประเภท WHT ได้เลยในบรรทัด — ระบบจะหักตอนจ่ายและออก 50 ทวิให้อัตโนมัติ
  • แนบรูปใบเสร็จรายบรรทัดได้ — คลิกไอคอนลูกศรท้ายแถวเพื่อเปิดหน้าต่างบรรทัดนั้น แล้วอัปโหลดรูปในช่อง "รูปใบเสร็จ" (ซูมดูได้)
  • ค่าใช้จ่ายเป็นของสาขาอื่น (เช่น ผู้จัดการเบิกจากกองสาขาตัวเอง แต่ไปทำงานอีกสาขา) — เลือกสาขานั้นในคอลัมน์ "สาขาที่ใช้" เฉพาะบรรทัดนั้น ระบบจะลง analytic สาขาที่เลือกแทนตอนสร้างบิล / ปล่อยว่าง = ลงสาขาของกองตามปกติ — เงินยังออกจากกองเดิมและเติมคืนกองเดิมเต็มยอด ไม่ต้องทำอะไรเพิ่ม
กรณีวิธีคีย์
บิลทั่วไป ไม่มีชื่อร้าน (วินมอเตอร์ไซค์, ตลาด, ค่ารถ) ปล่อยช่องร้านค้าเป็นค่าเริ่มต้น "ใบรับรองแทนใบเสร็จรับเงิน" และไม่เลือก VAT
ใบกำกับภาษี ต้องการขอคืน VAT เลือก vendor จริง ที่มีเลขผู้เสียภาษี + กรอกเลขที่ใบกำกับ + เลือกภาษีซื้อ 7% (ระบบบล็อกให้ถ้าลืม)
ใบเสร็จใบเดียว มีหลายหมวดค่าใช้จ่าย คีย์หลายบรรทัด ใช้ร้านเดียวกัน + เลขที่ใบเสร็จเดียวกัน ระบบจะรวมเป็น vendor bill ใบเดียวให้เอง
เบิกจากกองสาขานี้ แต่ค่าใช้จ่ายเป็นของสาขาอื่น (ไปทำงานต่างสาขา) เลือกสาขานั้นในคอลัมน์ "สาขาที่ใช้" ของบรรทัด — ค่าใช้จ่ายลง P&L สาขาที่ไปทำงาน ส่วนเงิน/การเติมเงินยังเป็นของกองสาขาผู้เบิกตามเดิม
เลขที่เอกสาร: ทุกเอกสารได้เลขอัตโนมัติจากตัวนับของระบบ แก้ไม่ได้ — ยกเว้นผู้ที่ฝ่ายบัญชีมอบสิทธิ์ "แก้เลขที่เอกสารเงินสดย่อย" (ตั้งที่ Settings > Users > แท็บสิทธิ์ > Other) ซึ่งแก้ได้เฉพาะตอนเอกสารยังเป็นร่าง เลขห้ามซ้ำกับเอกสารเดิม และการแก้ทุกครั้งถูกบันทึกในประวัติ (chatter) ว่าใครแก้จากเลขอะไรเป็นอะไร

แท็บ ③ จ่ายบิลตั้งหนี้

กดเพิ่มแล้วเลือกบิลเดิมจากระบบ — รายการที่ให้เลือกถูกกรองไว้แล้วเฉพาะเอกสารที่ใช้ได้ คือ vendor bill / ใบลดหนี้ผู้ขาย ที่ Post แล้ว + ยังไม่จ่าย/จ่ายบางส่วน และไม่ใช่บิลที่เกิดจากใบเคลียร์อื่น เมื่อดึงเข้ามาแล้วระบบทำให้:

  • ยอดค้างชำระของบิลนับเข้า "ยอดใช้จ่ายจริง" ของใบเคลียร์ → เงินคงเหลือกองลดถูกต้อง และยอดไปรวมในใบสรุปขอเติมเงินด้วย (ไม่งั้นเงินหายจากกล่องแต่ทะเบียนไม่รู้ เติมเงินคืนสาขาไม่ครบ)
  • ยอดที่นับเป็น snapshot ณ ตอนดึงเข้า — หลังจ่ายแล้วบิลค้าง 0 แต่ทะเบียนยังจำยอดที่กองออกเงินไว้
  • ตอนกด Post + จ่ายทั้งชุด ระบบ register payment ให้บิลใบนี้จาก journal เงินสดย่อยของสาขาพร้อมบิลอื่น รวมถึงหัก ณ ที่จ่ายถ้าบรรทัดบิลระบุ WHT ไว้
เคสบิลจาก PO: ดึง PO ตรง ๆ ไม่ได้ — ต้องตั้งหนี้จาก PO ก่อน (เปิด PO → ปุ่ม Create Bill → ตรวจ → Post) แล้วบิลจะมาโผล่ในหน้าต่างเลือกของแท็บนี้เอง ค้นหาด้วยเลข PO ในคอลัมน์ Source Document ได้เลย (หน้าต่างเลือกมีปุ่มให้เลือกอย่างเดียว สร้างเอกสารใหม่จากตรงนี้ไม่ได้ — เป็นความตั้งใจ กันสร้าง JE เปล่าโดยไม่รู้ตัว)
ระวัง: ถ้าดึงบิลตั้งหนี้เข้าใบเคลียร์แล้วจ่ายไปแล้ว จะยกเลิกใบเคลียร์ไม่ได้จนกว่าบัญชีจะยกเลิก payment ของบิลนั้นก่อน
คีย์ผิดหลังกด "สร้าง Vendor Bills" แล้ว: กดปุ่ม กลับเป็นร่าง ที่หัวใบได้เลย ไม่ต้องยกเลิกทั้งใบ — ระบบจะลบบิล draft ที่สร้างไว้ทิ้ง คืนใบเบิกกลับเป็น "จ่ายเงินแล้ว" และเก็บบิลตั้งหนี้ที่ดึงมาไว้ครบ แก้เสร็จกดสร้างบิลใหม่ได้ตามปกติ
ปุ่มนี้ใช้ได้เฉพาะตอนที่บิลยังเป็น draft ทุกใบ — ถ้า post หรือจ่ายไปแล้ว มีรายการบัญชีจริงเกิดขึ้น ต้องให้ฝ่ายบัญชี reset บิล/ยกเลิก payment ก่อน (ไม่งั้นทะเบียนกองกับบัญชีจะไม่ตรงกัน)
เคสมีใบลดหนี้ (ผู้ขายลดหนี้/คืนของ): ดึงใบลดหนี้เข้ามาในแท็บเดียวกันพร้อมบิลได้เลย (ตัวเลือกมีทั้ง Vendor Bill และ Vendor Credit Note ดูคอลัมน์ "ประเภท") — ยอดใบลดหนี้จะถูกหักออกจากยอดใช้จ่ายจริง และตอนกด Post + จ่ายทั้งชุด ระบบจะหักกลบบิลกับใบลดหนี้ของผู้ขายรายเดียวกันก่อน แล้วจ่ายเป็นยอดสุทธิก้อนเดียว เงินสดที่ออกจากกองจึงเท่ากับที่จ่ายจริง
ถ้าใบลดหนี้เท่ายอดบิลพอดี ระบบจะจับคู่ปิดกันเองโดยไม่มีเงินสดออกจากกอง / ถ้าใบลดหนี้มากกว่ายอดบิลระบบจะเตือนให้ดึงบิลของผู้ขายรายนั้นเข้ามาให้ครบก่อน (เงินที่ผู้ขายคืนเกินต้องให้บัญชีจัดการแยก)

ก่อนไปขั้นถัดไป — ตรวจยอดท้ายใบ

  • ตรวจ ยอดเบิก / ยอดจ่ายบิลตั้งหนี้ / ยอดใช้จ่ายจริง / เงินทอนคืนกอง ให้ตรงกับเงินทอนในซอง
ด่านกันพลาด: ระบบจะไม่ยอมสร้างบิลถ้า (1) กองมีใบเบิกค้างเคลียร์แต่ใบเคลียร์นี้ไม่ได้ดึงมาเลย หรือ (2) ยอดใช้จ่ายเกินยอดเบิก (เงินทอนติดลบ) — ถ้าเป็นเงินสำรองจ่ายจริง (สาขาจ่ายเองโดยไม่มีใบเบิก หรือจ่ายเกินที่เบิก) ให้ติ๊กช่อง "ยืนยันกรณีสำรองจ่าย" แล้วกดใหม่ — ช่องนี้โผล่เฉพาะตอนเข้าเงื่อนไขพิเศษ

3ลงบัญชี — เลือกได้ 2 ท่า

ท่าเร็ว (แนะนำ): กดปุ่มเดียว Post + จ่ายทั้งชุด — ระบบทำให้ครบ: สร้าง vendor bill ทุกใบ (แยกตามใบกำกับ, ใส่ analytic สาขา, กรอกแท็บ Tax Invoice จากเลขใบกำกับที่คีย์ไว้) → Post → จ่ายจาก journal เงินสดย่อยของสาขา → หัก ณ ที่จ่ายตามที่ระบุ พร้อมข้อมูลออก 50 ทวิ → จ่ายบิลตั้งหนี้ในแท็บให้ด้วย — จบในจอเดียว

ท่าตรวจก่อน: กด สร้าง Vendor Bills (draft) → เปิดปุ่ม Vendor Bills ตรวจทีละใบ แก้บัญชี/ภาษีได้ → Post → Register Payment เลือก journal สาขา (PCATZ, PCHO, ...) เอง — ใช้กับใบเคลียร์ที่ไม่แน่ใจ

  • รายการ VAT ไหลเข้ารายงานภาษีซื้อเอง (เลขใบกำกับ/วันที่ถูกกรอกให้จากบรรทัดใบเสร็จแล้ว)

4เติมเงินคืนสาขา

เงินสดย่อย → ขอเติมเงิน → New เลือกกอง → กด Add แล้วติ๊กเลือกใบเคลียร์จากรายการ (ระบบกรองเฉพาะใบสถานะ "สร้างบิลแล้ว" ของกองนี้ที่ยังไม่ถูกใบเติมเงินอื่นใช้ — รวมหลายใบได้, อย่ากดปุ่ม New ในหน้าต่างเลือก)

  • พิมพ์ ใบสรุปขอเติมเงินสดย่อย — ตาราง "สรุปตามหมวดบัญชี" คือตัวเลขสำหรับลงรายการ/ตรวจยอด (รวมบิลตั้งหนี้ที่จ่ายด้วยเงินสดย่อยแล้ว)
  • โอนเงินเข้าสาขา = internal transfer จากธนาคาร → journal เงินสดย่อยสาขานั้น ตามยอดในใบสรุป
  • ใส่เลขอ้างอิงการโอนในช่อง อ้างอิงรายการโอน/JE → กด เติมเงินแล้ว — ยอดกองกลับมาเต็ม 4,000

5JV ล้างบัญชีพัก 111001 (งานบัญชีตามรอบ เช่น สิ้นเดือน)

ทุกครั้งที่กดจ่ายบิลจากกอง เงินฝั่งบัญชีจะไปพักที่ 111001 บัญชีพักเงินจ่าย ก่อน (บัญชีเดียวกับที่ใบสำคัญจ่าย PVC ใช้อยู่ — รูทีนล้างเป็นแบบเดียวกัน) ฝ่ายบัญชีทำ JV ล้างตามรอบ:

รายการเดบิตเครดิต
ล้างส่วนของเงินสดย่อยเข้าบัญชีเงินสดย่อย111001 บัญชีพักเงินจ่าย111002 Petty Cash
  • เพราะ 111001 ใช้ร่วมกับ PVC — ยอดส่วนของเงินสดย่อยให้ดูจาก General Ledger ของ 111001 กรองเฉพาะ journal PCxxx หรือเทียบตาราง "สรุปตามหมวดบัญชี" ในใบสรุปขอเติมเงิน (ตัวเลขชุดเดียวกัน)
  • ล้างส่วนเงินสดย่อยครบเมื่อไหร่ ยอดสะสมฝั่งเครดิตของ journal PCxxx ใน 111001 ต้องเท่ากับยอดที่ JV ล้างไปแล้วพอดี

การนับเงินสด (Cash Count) — แนะนำทำเดือนละครั้งต่อสาขา

เครื่องมือตรวจว่าเงินจริงในกล่องของสาขาตรงกับทะเบียนหรือไม่ — ให้สาขานับเงินจริงแล้วแจ้งผล (หรือนับตอนเข้าตรวจสาขา) จากนั้นบัญชีคีย์:

เงินสดย่อย → นับเงินสด → New

  • เลือกกอง → ระบบดึงยอดตามทะเบียนมาให้อัตโนมัติ (กดปุ่ม ดึงยอดทะเบียน เพื่ออัปเดตใหม่ได้ขณะยังเป็นร่าง)
  • ใส่ชื่อผู้นับเงิน / ผู้ร่วมนับ แล้วกรอกจำนวนธนบัตร-เหรียญแต่ละชนิดที่นับได้จริง — ระบบรวมยอดและคำนวณผลต่างให้ทันที
  • ถ้ามีผลต่าง (เงินขาด/เงินเกิน) ต้องใส่คำอธิบายในช่องหมายเหตุก่อน ระบบถึงจะยอมให้กด ยืนยันผลนับ
  • พิมพ์ ใบนับเงินสดย่อย ให้ผู้นับ/ผู้ถือเงิน/ผู้ตรวจสอบเซ็นเก็บเข้าแฟ้ม
Tip: ผลต่างที่พบบ่อยเกิดจากบิลที่สาขาจ่ายแล้วแต่ยังไม่ส่งมาเคลียร์ — ถ้านับก่อนวันตัดรอบส่งเอกสาร ให้ระบุในหมายเหตุว่ารอบิลชุดไหน

การพิมพ์เอกสาร

ทุกเอกสารพิมพ์จากปุ่ม Print ด้านบนของฟอร์ม (รูปเฟือง/เมนูพิมพ์):

เอกสารพิมพ์จากใช้ทำอะไร
ใบเบิกเงินสดย่อยใบเบิกแนบซองเอกสาร ให้ผู้เกี่ยวข้องเซ็นย้อนหลัง/เก็บแฟ้ม
ใบสำคัญจ่ายเงินสดย่อยใบเคลียร์สรุปใบเสร็จ+บิลตั้งหนี้ทั้งชุด + ยอดเบิก/ใช้จริง/เงินทอน เก็บคู่กับซอง
ใบสรุปขอเติมเงินสดย่อยขอเติมเงินเอกสารประกอบการโอนเติมเงิน + สรุปหมวดบัญชีสำหรับลงรายการ
ใบนับเงินสดย่อยนับเงินสดผลนับเงินจริงแตกชนิดธนบัตร/เหรียญ เทียบทะเบียน ให้เซ็นรับรอง

การแก้ไข / ยกเลิก

เอกสารเงื่อนไขการยกเลิก
ใบเบิก ยกเลิกได้ถ้ายังไม่ถูกเคลียร์ — ถ้าเคลียร์แล้วต้องยกเลิกใบเคลียร์ก่อน
ใบเคลียร์ กด ยกเลิก ได้ตราบใดที่บิลยังไม่ Post (ระบบยกเลิก draft bill ให้ และคืนสถานะใบเบิกเป็น "จ่ายเงินแล้ว") — ถ้าบิล Post/จ่ายแล้ว ต้องให้บัญชียกเลิก payment และ Reset to Draft บิลก่อน
ขอเติมเงิน ยกเลิกได้ — ใบเคลียร์ในชุดจะกลับเป็น "สร้างบิลแล้ว" เลือกเข้าใบเติมเงินใหม่ได้
นับเงินสด เอกสารที่ยืนยันแล้วต้องกดยกเลิกก่อนถึงจะลบได้

VAT: รายการขอคืน VAT ต้องเลือก vendor จริงที่มีเลขผู้เสียภาษี + กรอกเลขที่ใบกำกับเสมอ — ห้ามใช้ partner กลาง "ใบรับรองแทนใบเสร็จรับเงิน" (ระบบบล็อกให้ แต่ควรเช็คตั้งแต่รับเอกสารว่าใบกำกับภาษีเต็มรูปหรือไม่)
จ่ายบิลตั้งหนี้ด้วยเงินสดย่อย ต้องผ่านแท็บ "จ่ายบิลตั้งหนี้" ในใบเคลียร์เท่านั้น — ถ้าไปกด Register Payment เลือก journal PCxxx เองนอกใบเคลียร์ ทะเบียนกองจะไม่รู้ ยอดเงินคงเหลือจะเพี้ยนจากเงินจริง
เงินทอนติดลบ: ถ้ายอดใช้จริงมากกว่ายอดเบิก (สาขาสำรองจ่าย) ช่อง "เงินทอนคืนกอง" จะติดลบ — ในฟอร์มพิมพ์จะขึ้นเป็น "จ่ายคืนผู้สำรองจ่าย" อย่าลืมคืนเงินสาขาด้วย
ตรวจกระทบยอด: เงินสดจริงในกล่องของสาขา ควรเท่ากับช่อง "เงินคงเหลือในกอง" ในหน้ากองเงินสดย่อยเสมอ — ถ้าไม่ตรง แปลว่ามีเอกสารตกค้างยังไม่ได้คีย์ หรือยังไม่ได้กดยืนยันสักขั้น (ใช้เมนูนับเงินสดช่วยตรวจ)
