# ตัวดึงเวลาตอกบัตรจากเครื่องสแกนนิ้ว (BpControl → Odoo)

เฟส 2 ของระบบเงินเดือน — ขั้นแรก: เก็บเวลาทำงานขนานไปกับ Business Plus
เพื่อสะสมข้อมูลไว้เทียบผลก่อนตัดระบบจริงในปี พ.ศ. 2570

## โซ่ข้อมูล

```
เครื่องสแกนนิ้ว  →  โปรแกรม Windows  →  SQL Server: BpControl.dbo.ScanData  →  [โมดูลนี้]  →  hr.attendance
```

`ScanData` = สรุปรายวัน 1 แถวต่อ พนักงาน 1 คน / 1 วัน / 1 สาขา มี 6 ช่องเวลา

| ช่อง | ความหมาย | กลายเป็น |
|---|---|---|
| `m1` / `m2` | เข้า-ออก ช่วงเช้า | บันทึกเวลา 1 แถว (slot `m`) |
| `a1` / `a2` | เข้า-ออก ช่วงบ่าย | บันทึกเวลา 1 แถว (slot `a`) |
| `e1` / `e2` | เข้า-ออก ช่วงเย็น/โอที | บันทึกเวลา 1 แถว (slot `e`) |

## การตั้งค่า

Settings → Technical → System Parameters

| พารามิเตอร์ | ค่าเริ่มต้น / หมายเหตุ |
|---|---|
| `bpcontrol.server` | ถ้าไม่ตั้ง ใช้ `bplus.server` |
| `bpcontrol.database` | `BpControl` |
| `bpcontrol.user` | ถ้าไม่ตั้ง ใช้ `bplus.user` |
| `bpcontrol.password` | ถ้าไม่ตั้ง ใช้ `bplus.password` |
| `bpcontrol.driver` | ปล่อยว่างให้เลือก ODBC Driver เองอัตโนมัติ |
| `bpcontrol.sync_days` | `14` — cron ดึงย้อนหลังกี่วันทุกรอบ (ตั้ง 14 เพราะบางสาขาส่งข้อมูลช้า 4-5 วัน) |

**ควรใช้ login ที่อ่านได้อย่างเดียว** (เช่น `odoo_reader` ที่มีสิทธิ์ db_datareader บน BpControl)
ไม่ควรใช้ `sa`

## การใช้งาน

- **อัตโนมัติ**: cron "ดึงเวลาตอกบัตรจากเครื่องสแกน (BpControl)" วันละครั้ง ตี 5 ครึ่ง (22:30 UTC)
  ดึงย้อนหลัง 14 วันทุกรอบ เพราะหัวหน้าสาขายังแก้เวลาของวันก่อน ๆ ได้ และบางสาขาส่งข้อมูลช้า
  *(เปิดใช้งานแล้วบน Autozone-PD ตั้งแต่ 11 ก.ย. 2026 — การดึงซ้ำที่ไม่มีอะไรเปลี่ยนใช้เวลา <1 วินาที)*
- **สั่งเอง**: Attendances → Configuration → **ดึงเวลาจากเครื่องสแกน** (เลือกช่วงวันที่)
- **ดูผล**: Attendances → Configuration → **ประวัติการดึงเวลา**

## หลักการที่ต้องรู้

1. **เวลา** — ฝั่ง BpControl เก็บเป็นเวลาไทย, `hr.attendance` เก็บเป็น UTC โมดูลแปลงให้อัตโนมัติ
   ถ้าตรวจด้วย SQL ต้องแปลงกลับ: `(check_in at time zone 'UTC') at time zone 'Asia/Bangkok'`
2. **จับคู่พนักงาน** — `atzScanId` = `registration_number` (รหัส 5 หลัก) เท่านั้น ไม่จับคู่ด้วยชื่อ
   คนที่ยังไม่มีใน Odoo จะถูกรายงานเป็น "ไม่พบพนักงาน" ไม่ทำให้การดึงล้ม
3. **ดึงซ้ำได้** — คีย์ `az_source_key` = `สาขา|รหัส|วันที่|ช่วง`
   ต้นทางแก้เวลา → อัปเดตตาม | ต้นทางลบแถว → ลบตาม | เหมือนเดิม → ไม่แตะ
4. **ตอกเข้าไม่ตอกออก** — ไม่สร้างแถวค้างไว้ (จะทำให้ Odoo คิดว่าพนักงานยังไม่เลิกงาน)
   แต่นับไว้ในช่อง "ตอกเข้าไม่ตอกออก" ให้เห็นว่าวันนั้นข้อมูลไม่ครบกี่เคส
5. **ไม่แตะข้อมูลที่คีย์เอง** — ทำงานเฉพาะแถวที่ `az_source = bpcontrol` เท่านั้น
   แถวที่คีย์เอง/มาจาก Kiosk ปลอดภัย (ดูได้จากคอลัมน์ "ที่มาของข้อมูล")

## การจัดการข้อมูลต้นทางที่ไม่สมบูรณ์ (v1.1.0)

ต้นทางมี 2 กรณีที่ทำให้บันทึกเวลาซ้อนกัน ซึ่ง Odoo ไม่ยอมรับ โมดูลจัดการให้อัตโนมัติ
และนับจำนวนไว้ในประวัติการดึงทุกรอบ

**1. คนเดียว วันเดียว มีข้อมูลมากกว่า 1 สาขา** (ช่อง "ซ้ำข้ามสาขา")
เกิดตอนพนักงานย้ายสาขา หรือหัวหน้า 2 สาขาต่างคนต่างกรอกให้ — พบ 122 คน-วัน ใน 9 เดือน (0.16%)
ระบบเลือกไว้สาขาเดียว โดยเลือกแถวที่ **"ดูเป็นการสแกนจริง"** มากที่สุด:
เวลาที่คนกรอกเองมักลงตัวเป๊ะ (08:00:00, 13:00:00) ส่วนเวลาที่สแกนจริงมักมีเศษ (07:57:15)
ถ้าคะแนนเท่ากันใช้สาขาที่รหัสน้อยกว่า เพื่อให้ดึงกี่รอบก็ได้ผลเดิม

**2. ช่วงเวลาทับกันเองในแถวเดียว** (ช่อง "ช่วงเวลาทับกัน")
เช่น บ่าย 13:00-21:30 กับ โอที 17:30-21:30 = คนตอกออกครั้งเดียวตอนจบโอที
แต่ช่องโอทีถูกกรอกเพิ่ม ถ้าปล่อยไว้ชั่วโมงจะถูกนับซ้ำ
ระบบตัดหัวช่วงหลังให้เริ่มตอนช่วงก่อนหน้าจบ ถ้าจมอยู่ในช่วงก่อนทั้งหมดก็ตัดทิ้ง
(ได้ผลเท่ากับ "รวมช่วงเวลา" — ไม่มีทางนับซ้ำ และไม่ทำให้เวลาหายไป)

> ทั้งสองกรณีเป็นปัญหาที่ต้นทาง ไม่ใช่ของ Odoo — ตัวเลขในช่องนี้ใช้เป็นสัญญาณว่า
> ควรไปคุยกับสาขาให้กรอกข้อมูลให้ถูกหรือไม่

## ผลทดสอบ (11 ก.ย. 2026)

ข้อมูลจริงวันที่ 9 ก.ย. 2026 (211 แถวต้นทาง / พนักงาน 206 คน)

| สถานการณ์ | ผลที่ได้ |
|---|---|
| ดึงรอบแรก | สร้าง 413 แถว, ไม่พบพนักงาน 5 คน (รหัสใหม่ที่ HR ยังไม่สร้างใน Odoo) |
| ดึงซ้ำช่วงเดิม | สร้าง 0 / เหมือนเดิม 413 — ไม่เกิดข้อมูลซ้ำ |
| ต้นทางแก้เวลา 1 คน | แก้ 1 แถว เวลาตรงตามต้นทาง |
| ต้นทางลบ 1 คน | ลบ 2 แถว (คนนั้นมี 2 ช่วง) |
| ตรวจเวลาแบบสุ่ม 50 คน | ตรงกับต้นทาง 50/50 |

## ข้อจำกัดที่รู้อยู่

- ต้องมี `pyodbc` + ODBC Driver บนเครื่องที่รัน Odoo (ถ้าไม่มี จะถอยไปใช้ `sqlcmd` ให้อัตโนมัติ)
- ใช้คลาส `Db` ร่วมกับโมดูล `import_payslip_inputs` (ไฟล์ `tools/bplus_extract.py`)
  ถ้าวันหนึ่งเลิกใช้โมดูลนั้น ต้องย้ายคลาส `Db` มาไว้ในโมดูลนี้ก่อน
- ยังไม่คำนวณสาย/ขาด/โอที — ขั้นนี้เก็บเวลาดิบอย่างเดียวตามที่ตกลงไว้
