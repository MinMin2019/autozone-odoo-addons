# ตารางแม็ปปิ้ง: ระบบเดิม → Input Type → Salary Rule → บัญชี (เฟส 1, โมเดล A)

> **อัปเดต 8 ก.ย. 2026:** ตารางฉบับปัจจุบัน (1 รหัส Business Plus = 1 บรรทัดสลิป, 186 rules) อยู่ที่ `BPLUS_CODE_MAP.md` ซึ่ง generate จาก `tools/gen_payroll_config.py` — เอกสารนี้เก็บไว้เป็นที่มาของบัญชีที่บัญชียืนยัน 6 ส.ค. 2026 และกลไกเครื่องหมาย Dr/Cr


> **หลักการ**: ระบบเดิมเป็นเครื่องคิดเลข Odoo รับยอดสำเร็จรูปผ่าน Other Inputs
> แล้วทำหน้าที่ออกสลิป + ลงบัญชีเท่านั้น (Structure: **เงินเดือน - นำเข้าจากระบบเดิม (Legacy Import)**)

## สิ่งที่ฝ่ายบัญชีต้องตั้งค่าก่อนใช้งานจริง (ครั้งเดียว)

1. **Journal**: สร้าง/เลือกสมุดรายวัน "เงินเดือน (Payroll)" แล้วตั้งที่
   *Payroll → Configuration → Structures → Legacy Import → Accounting → Salary Journal*
2. **บัญชี Dr/Cr ของแต่ละ Rule**: เปิด Structure → เข้าแต่ละ Salary Rule → แท็บ *Accounting*
   → ใส่ Debit/Credit Account ตามตารางข้างล่าง (เลขบัญชีให้เติมตามผังบัญชีจริงของบริษัท)
3. ตั้ง **Salary Structure Type** บนสัญญาจ้างของพนักงานทุกคนเป็น
   **"พนักงาน - นำเข้าจากระบบเดิม (Legacy Import)"** — ตอน Generate Payslips
   ระบบจะเลือก Structure Legacy Import ให้อัตโนมัติ

### รายการหัก (ยอดใน rule ติดลบ → Odoo กลับข้างเป็น Credit เข้าบัญชีเจ้าหนี้/ค้างจ่าย)

> ⚠️ **Gotcha สำคัญ (เจอจริง 20 ส.ค. 2026)**: บัญชีของ rule รายการหักต้องใส่ในช่อง
> **Debit Account** ไม่ใช่ Credit Account! — core (`hr_payroll_account/_prepare_slip_lines`)
> พลิกข้างตามเครื่องหมายของยอด: ยอดติดลบ + account_debit → JE ออกเป็น **Credit** (ถูก),
> ยอดติดลบ + account_credit → JE ออกเป็น **Debit** (กลับหัว แล้วถ่วงดุลเข้าบัญชี default ของ journal)
> กติกา: rule รายได้ (ยอดบวก) ใส่ช่องตามข้างจริง / rule รายการหัก (ยอดติดลบ) ใส่ช่อง **Debit** เสมอ
> คอลัมน์ "Cr" ในตารางล่างหมายถึง *ข้างที่ปรากฏใน JE* ไม่ใช่ชื่อช่องที่กรอก

### ยอดรวม

| Rule | หน้าที่ | บัญชี |
|---|---|---|
| GROSS (รวมรายได้) | ยอดรวมแสดงบนสลิป | ไม่ต้องผูกบัญชี |
| NET (เงินได้สุทธิ) | ยอดจ่ายจริง | Cr: 21xx เจ้าหนี้เงินเดือนค้างจ่าย (Payable) |

> **เช็คความถูกต้องของสมการบัญชี**: Dr รวมรายได้ทุกตัว = Cr รายการหักทุกตัว + Cr NET
> ถ้า journal entry ไม่ดุล แปลว่า rule ไหนสักตัวยังไม่ได้ผูกบัญชี

## กติกาของไฟล์ Import (ให้ HR ใช้)

- จับคู่พนักงานด้วย **รหัสพนักงาน (Registration Number)** เท่านั้น — ตั้งค่าที่ Employee → HR Settings
- **จำนวนเงินใส่ค่าบวกเสมอ** ทั้งรายได้และรายการหัก (rule ฝั่งหักจะติดลบให้เอง)
- แถวที่ (พนักงาน + code) ซ้ำกัน ระบบจะ**รวมยอด**และแจ้งใน Preview
- Import ซ้ำ = **ล้างรายการที่เคย import แล้วลงใหม่ตามไฟล์ล่าสุด** (ไฟล์คือความจริงเสมอ; รายการที่กรอกมือไม่ถูกแตะ)
- เพิ่มรายได้/รายการหักประเภทใหม่: สร้าง Input Type + สร้าง Salary Rule ใน Structure + ผูกบัญชี ครบ 3 อย่างเสมอ
  (ถ้ามี Input แต่ไม่มี Rule ระบบ import จะฟ้อง error ไม่ปล่อยผ่าน)

## โฟลว์ประจำเดือน

1. HR สร้าง Payslip Batch → **Generate Payslips** (เลือกพนักงาน/Structure Legacy Import)
2. กด **Import Inputs (Excel)** → อัปโหลดไฟล์จากระบบเดิม → ตรวจยอดสรุปหน้า Preview
   (เทียบ "รวมรายได้/รวมรายการหัก" กับรายงานระบบเดิมก่อนกดยืนยัน)
3. ยืนยัน → ระบบลง input + คำนวณสลิปใหม่อัตโนมัติ + บันทึก log ลง chatter ของ Batch
4. HR สุ่มตรวจสลิปรายคน → Confirm Batch → Odoo สร้าง draft journal entry
5. บัญชี review entry → post
6. **ช่วง Parallel run (1–2 เดือนแรก)**: เทียบเงินได้สุทธิรายคน + ยอดรวม GL กับระบบเดิมทุกงวด
