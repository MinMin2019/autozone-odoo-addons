# ส่งมอบโมดูล import_payslip_inputs ให้ทีม IT (4 พ.ย. 2569)

ตั้งแต่วันนี้ โมดูลนี้เป็นความรับผิดชอบของทีม IT เพื่อให้ข้อมูลพนักงานกับเงินเดือนดูแลโดยทีมเดียวกัน
เอกสารนี้สรุปสิ่งที่อ่านจากโค้ดไม่เห็น ได้แก่ การตั้งค่าบนเซิร์ฟเวอร์ ข้อตกลงที่เจ้าของงานเคาะแล้ว กับดัก และงานที่ค้าง

สถานะ ณ วันส่งมอบ: **18.0.3.4.1** ติดตั้งแล้วบน prod (Autozone-PD) และ Dev (Autozone-Dev), commit 1b64895 บน main

---

## 1. โมดูลนี้ทำอะไร

ระบบเงินเดือนยังคำนวณใน **Business Plus (BPlus)** โมดูลนี้นำผลลัพธ์รายคนเข้า Odoo เพื่อออกสลิปและลงบัญชี ไม่ได้คำนวณเงินเดือนเอง

1. HR สร้าง Payslip Batch ช่วง 22 ถึง 21 ของเดือนถัดไป (ตรงกับงวด BPlus) แล้วกด Generate Payslips
2. กด **Import Inputs** แล้วเลือก "ดึงจาก Business Plus" (หรืออัปโหลดไฟล์ Excel จาก `tools/bplus_extract.py`)
3. wizard ตรวจสมการ `รายได้ − หัก = สุทธิ` รายคน ถ้าไม่ลงจะบล็อก จากนั้นเทียบ NET ของสลิปกับสุทธิของ BPlus อีกรอบ
4. กด **Create Draft Entry** ระบบสร้างใบสำคัญ **1 ใบต่อสาขา** แบบดราฟ ให้บัญชีตรวจและ post เอง

หลักการ: **1 รหัสรายการใน BPlus = 1 input type = 1 salary rule** ตารางแม็ปอยู่ใน `doc/BPLUS_CODE_MAP.md` และสร้างจาก `tools/gen_payroll_config.py`

## 2. การตั้งค่าบนเซิร์ฟเวอร์

| รายการ | ค่า |
|---|---|
| ฐาน BPlus | SQL Server 2022 ฐาน `PayrollAutozone` บนเครื่อง az-server-03 (LAN 192.168.100.5) |
| ทางเชื่อมจาก prod | Tailscale 100.80.72.60 พอร์ต 1433 (ห้ามเปิด 1433 ออกอินเทอร์เน็ต) |
| ผู้ใช้ SQL | `odoo_reader` อ่านอย่างเดียว (สร้างด้วย `tools/create_bplus_reader_login.sql`) |
| System Parameters | `bplus.server`, `bplus.database`, `bplus.user`, `bplus.password`, `bplus.driver` (ปล่อยว่างได้), `bplus.loan_source` |
| ไดรเวอร์บน prod | pyodbc + ไดรเวอร์เก่า "SQL Server" ของ Windows ใช้ได้ ไม่ต้องลง ODBC Driver 17 |

รหัสผ่านของ `odoo_reader` ไม่อยู่ในเอกสารนี้ ให้ขอจากเจ้าของระบบเดิม

**โหมดเงินกู้ (เคาะแล้ว):** `bplus.loan_source = bplus` คือหักเงินกู้ตามยอด BPlus (รหัส 2320 เข้าเป็นบรรทัด LOAN) ทะเบียน `custom_hr_loan` ใช้ดูและเทียบเท่านั้น **ห้ามกดปุ่ม "หักเงินกู้พนักงาน" ซ้ำ** ไม่งั้นหักสองรอบ

## 3. ข้อตกลงที่เจ้าของงานเคาะแล้ว

- **สาขาในใบสำคัญอ่านจาก analytic บนสัญญาจ้าง** ไม่ได้อ่านจาก analytic ของแผนกในผังองค์กร (เคาะ 4 พ.ย. 2569) ณ วันส่งมอบมี 9 คนที่สองแหล่งไม่ตรงกัน ถ้าจะเปลี่ยนมาใช้แผนก ต้องถามเจ้าของงานก่อน
- **ชื่อใบสำคัญตัดเลขลำดับนำหน้ารหัสสาขา** บัญชีตั้งรหัส analytic บางกลุ่มเป็น "1 ATP" หรือ "2 HTR" ชื่อใบสำคัญจะแสดงเป็น "October 2026 - ATP" ส่วนรหัสใน analytic ไม่ได้ถูกแก้
- **Job Level ใช้ของ `autozone_org_chart` (hr.job.job_level) ที่เดียว** ช่อง `job_level` ของโมดูลนี้บน hr.employee ถูกซ่อนจากฟอร์มแล้ว แต่**ฟิลด์และข้อมูลยังอยู่** (456 คน) ดูหัวข้อ 6
- `title_th` (คำนำหน้าชื่อ) ของโมดูลนี้ถูก `autozone_hr_employee` (พิมพ์สัญญา) และ `autozone_hr_recruitment` อ่านใช้อยู่ ถ้าจะย้ายไปโมดูล HR ต้องย้ายพร้อมข้อมูล

## 4. กับดัก (อ่านก่อนแก้หรือ deploy)

1. **ห้ามรัน `tools/wire_payroll_accounts_shell.py` บน prod หรือ Dev**
   บัญชีเปลี่ยนบัญชีของ salary rule บน prod เอง 33 รายการ เช่น ค่าตำแหน่งไปลง 512004 และเงินกู้/หักอื่นไปลง 123001 แทน 154101 ที่ถูกยกเลิกแล้ว
   ตาราง MAP ในสคริปต์ยังเป็นชุดเก่า ตอนนี้สคริปต์ล้มที่บัญชี 154101 ก่อน commit จึงยังไม่เสียหาย แต่ถ้ามีใครสร้าง 154101 ขึ้นมา สคริปต์จะทับค่าของบัญชีทั้งหมด
   ถ้าจะใช้อีก ต้อง sync MAP ใน `gen_payroll_config.py` จากค่าในฐาน prod ก่อน
2. **record ใน XML (structure, rule, input type) เป็น noupdate** การ `-u` จะไม่ทับค่าที่บัญชีแก้ วิธี deploy ที่ใช้ตั้งแต่ 3.4.1 คือ snapshot rule/บัญชีก่อนและหลัง `-u` แล้วเทียบกัน ต้องได้ผล IDENTICAL (ตัวอย่างสคริปต์อยู่บนเซิร์ฟเวอร์ที่ `C:\Users\Administrator\ipi341\`)
3. **Dev ใช้โฟลเดอร์ custom_addons ร่วมกับ prod** คัดลอกไฟล์ลงไปเพื่อเทส Dev แปลว่า prod ได้ไฟล์ใหม่ไปด้วย prod จะเริ่มใช้เมื่อรีสตาร์ทหรือ `-u` ถ้าแก้แค่ Python ให้รีสตาร์ท service อย่างเดียว ไม่ต้อง `-u`
4. **กันกด Create Draft Entry ก่อนนำเข้า** (`action_payslip_done`) สลิปของโครงสร้างโมดูลนี้ที่ไม่มี input ที่ import มา จะถูกบล็อกทั้ง Batch HR ต้องลบสลิปของคนที่ไม่มีใน BPlus เดือนนั้นออกก่อน
5. **พนักงานที่มีใน BPlus แต่ไม่มีสลิปใน Batch** ทำให้นำเข้าไม่ผ่านทั้งไฟล์ สาเหตุที่พบบ่อยคือยังไม่มีสัญญา สัญญายังเป็นร่าง สัญญาตั้ง Salary Structure Type ผิด (ต้องเป็นแบบ Legacy Import) หรือพนักงานถูก archive แล้วแต่ BPlus ยังจ่าย
6. **พนักงานที่ BPlus ลบแล้วสร้างใหม่จะได้ EMP_KEY ใหม่** โมดูลจับคู่ด้วย `PRS_NO` = `registration_number` จึงไม่มีผล แต่ประวัติงวดเก่าใน BPlus อาจหาย
7. **เครื่อง SQL Server มีการ์ดแลน 2 ตัว** การ์ดหลักคือ vEthernet (ExternalSwitch) 192.168.100.5 ห้ามแตะ เมื่อ 31 ต.ค. 2569 การ์ด Intel ตัวที่สองได้ DHCP 192.168.123.x จากเราเตอร์ที่ไม่มีเน็ต แล้วแย่ง default route ทำให้ Tailscale หลุด 3 วัน แก้แล้วด้วย `Set-NetIPInterface -InterfaceMetric 500` บนการ์ดตัวนั้น ถ้าปุ่มดึง BPlus ฟ้องว่าต่อไม่ได้ ให้เช็ค `tailscale status` จาก prod ก่อน

## 6. แผนถอดช่อง job_level ของโมดูลนี้

1. HR ตรวจไฟล์ `ตรวจระดับตำแหน่งพนักงาน_20261104.xlsx` (34 คน: ระดับต่างจากตำแหน่ง 21, ตำแหน่งยังไม่มีระดับ 12, ไม่มีตำแหน่ง 1) แล้วแก้ที่ตำแหน่งงานหรือย้ายพนักงานไปตำแหน่งที่ถูก
2. เมื่อไม่เหลือรายการค้าง ค่อยลบฟิลด์ `job_level` ออกจาก `models/hr_employee.py` การลบฟิลด์ทำให้คอลัมน์และข้อมูลหาย ควร export ค่าเดิมเก็บไว้ก่อน
3. `tools/convert_employees.py` ยังเขียน `job_level` อยู่ แต่เป็นสคริปต์ย้ายข้อมูลครั้งแรกเท่านั้น ไม่ได้ใช้แล้ว
